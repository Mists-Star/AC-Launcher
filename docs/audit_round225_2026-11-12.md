## 1. P0（1 条）

### P0-1 · OptiFine 通道远端文件名未过 `_safe_filename`，可写穿 mods 目录 · **已复现**

- `src/net_api.py:2891-2908`（对照正确写法 `src/net_api.py:849-854`、`:3217`）
- 根因：adloadx 页面正则抓到的 `f2` 直接拼进落盘路径与 URL：
  ```python
  f2, token = m.group(1), m.group(2)
  dest = os.path.join(dest_dir, f2)             # 无 basename / 无长度限制
  return parallel_download_file(
      OPTIFINE_DOWNLOADX.format(file=f2, token=token), dest, ...)
  ```
  既不 `quote`，也不传 `expected_sha1`；这是全仓**唯一**绕过 `_safe_filename` 的落盘点。
- 触发：资源中心 → OptiFine 分类安装；上游页面 / 镜像返回带 `../`（或 `? #`、超长名）的 `f=`。
  文件会写到 `mods/` 之外并被 `os.replace` 转正；`?` 还会截断 URL 下到错文件且无 hash 兜底。
- **行为复现**：注入被污染的页面后抓到
  `dest = <temp>/mods/../evil.jar`、`url = https://optifine.net/downloadx?f=../evil.jar&x=…`。
- 最小修法：`dest = os.path.join(dest_dir, _safe_filename(f2))`；URL 侧对 `f2` 做 `quote`；
  顺手把上游给的 hash（若有）透给下载器。
- 备注：需要上游被污染/劫持才触发，因此按「不可信输入」处理；修法只需两行，建议最先动。
